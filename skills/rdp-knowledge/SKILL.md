# למידה ארגונית משותפת

1. Identify a demonstrated reusable lesson and the evidence behind it. Decide whether it belongs in a skill, shared technical component or the project's own documentation.
2. Remove customer identifiers, credentials, records, private project URLs and proprietary customer rules. If sanitization would destroy the meaning, keep it in the authorized project.
3. Draft the general lesson in docs/ai/KNOWLEDGE.md using the project template, including applicability and a regression scenario. Review its content before copying anything to rdp-team/rdp-ai-skills.
4. For an authorized contribution, use a dedicated branch and PR in the shared repository. Update the focused skill/reference and its regression coverage. Reusable production code for Priority stays in rdp-priority-shared-components.
5. A proposal is not automatically approved organizational policy. Publish a new version after review; projects receive an update PR and retain their current version until that PR is approved.
